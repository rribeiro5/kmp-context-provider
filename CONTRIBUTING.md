# Contributing to kmp-context-provider

Thank you for taking the time to contribute!

> [!NOTE]
> **Project Scope & API Stability:**
> There are currently **no major API changes planned** for `kmp-context-provider`. The primary focus of ongoing maintenance is dependency updates and security patches.
> 
> However, if you discover a bug, performance bottleneck, or have a relevant improvement, contributions are very welcome!

## Community & Behavioral Expectations

We are committed to providing a welcoming, respectful, and harassment-free environment for everyone, regardless of background, experience level, or identity.

- Be respectful, constructive, and empathetic in all interactions (issue comments, code reviews, PR discussions).
- Focus on what is best for the community and project.
- Gracefully accept constructive criticism.

## Policy on AI Assistance

Using AI tools (such as GitHub Copilot, ChatGPT, Claude, or Gemini) is permitted and welcomed to help write code, generate tests, or draft documentation, provided you follow these rules:

- **Understand & Review:** You must thoroughly review, understand, and test any code generated by AI before submitting a Pull Request.
- **Accuracy & Quality:** AI-generated code must adhere to the project's coding standards, Detekt rules, and architecture.
- **No Untested Submissions:** Do not open PRs with unverified or blindly pasted AI output.

## How to Contribute

### 1. Reporting Issues

Before creating a new issue, please search existing open and closed issues to check if the topic has already been discussed.

- **Bug Reports:** Use the Bug Report template. Please include clear steps to reproduce, minimal code snippets, expected vs. actual behavior, and environment details.
- **Feature Requests / Enhancements:** Use the Feature Request template to describe the problem, the proposed solution, and example usages.

### 2. Submitting Pull Requests

1. **Fork the Repository:** Create a personal fork of `kmp-context-provider` on GitHub.
2. **Create a Topic Branch:** Create a branch for your work:
   ```bash
   git checkout -b feature/your-improvement
   ```
3. **Make Your Changes:**
   - Keep changes focused and consistent with the existing codebase style (`explicitApi = Strict`).
   - Add KDoc documentation for any new or modified public APIs.
   - Include unit tests for new functionality or bug fixes.
4. **Run Local Verification:** Ensure all linting, build, and test suites pass locally before submitting:
   ```bash
   # Run Detekt static analysis
   ./gradlew detekt

   # Run all unit tests and checks
   ./gradlew check

   # Run instrumented device tests (requires running Android emulator or connected device)
   ./gradlew connectedAndroidDeviceTest

   # Verify Dokka documentation generation
   ./gradlew dokkaGenerate
   ```
5. **Open a Pull Request:**
   - Push your branch to your fork and submit a Pull Request targeting the `main` branch.
   - Provide a clear description following the Pull Request template.
